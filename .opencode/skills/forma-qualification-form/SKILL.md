# FORMA Qualification Form

## Когда использовать

Используй этот Skill, когда нужно построить или проверить статическую анкету для
студии интерьера: шесть шагов, обязательные поля, проверка ответов, карточка
менеджера, предварительный статус, копирование и восстановление черновика.

## Границы

- Skill не расширяет разрешения агентов. Каждый агент действует только в рамках
  своих прав.
- `references/` доступен только для чтения.
- Нельзя выдумывать реальные имена, телефоны, адреса, платежи и персональные
  данные.
- Приложение создаётся и изменяется только внутри `app/`.
- Нельзя добавлять фреймворки, сборщики, CDN, внешние шрифты, API, CRM, PDF,
  аналитику и сетевые запросы.
- Статус и причины видны только в карточке менеджера.
- Автоматический отказ клиенту запрещён: решение принимает человек.
- Skill сам не изменяет файлы. Это делает Build после разрешения человека.

## Workflow

1. **Чтение исходников.** Прочитай `AGENTS.md`, `references/requirements.md`,
   `references/acceptance-report.md`, исходные документы и файлы `app/`.
   Зафиксируй поля, шаги, тексты и правила.
2. **`/forma-plan`.** Спроектируй экраны, модель ответов, валидацию, дерево
   статусов, хранение и адаптив. Не меняй файлы.
3. **Подтверждение.** Покажи человеку спорные правила, объём этапа и риски.
   Дождись явного разрешения.
4. **`/forma-build`.** Реализуй только согласованный этап внутри `app/`.
   Сохраняй работающие части и явно описывай изменения данных.
5. **Проверка.** Запусти `node scripts/validate.mjs`, пройди ручной сценарий из
   `docs/QA-CHECKLIST.md`, включая 1440, 768, 390 и 360 px и клавиатуру.
6. **`/forma-qa`.** Передай приложение на независимый аудит. QA возвращает
   таблицу доказательств и один статус, но ничего не исправляет.
7. **Согласованные исправления.** После разрешения человека исправь только
   подтверждённые пункты и повтори проверку.

## Критерии результата

- Работают приветствие, шесть шагов и прогресс «Шаг N из 6».
- Переход блокируется при невалидных обязательных полях.
- Фокус переходит на первое невалидное поле.
- Экран проверки показывает все ответы и открывает нужный шаг.
- После правки пользователь возвращается на проверку.
- «Отправить» показывает «Спасибо, менеджер свяжется с вами».
- Карточка содержит все заполненные поля, статус, причины и оговорку.
- Статусы `Приоритетная`, `Нужно уточнить` и `Не наш формат` совпадают с
  контрольными примерами L-001…L-008.
- Необязательные поля не влияют на статус.
- Статус не виден на клиентских экранах.
- Копирование работает, а при недоступности Clipboard API есть текстовый
  fallback.
- Черновик восстанавливается после перезагрузки.
- «Новая анкета» очищает черновик и результат.
- Нет сетевых запросов, внешних зависимостей и реальных данных.
- Интерфейс читаем на 1440, 768, 390 и 360 px и доступен с клавиатуры.
- `references/` не изменён, QA вернул независимый отчёт.

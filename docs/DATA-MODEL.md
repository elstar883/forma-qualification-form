# Модель данных «FORMA — анкета квалификации обращений»

Все данные демонстрационные. Реальные персональные сведения, телефоны,
платёжные и паспортные данные не используются.

## 1. Объект ответов

Приложение хранит один плоский объект `answers`:

```js
{
  name: "Ольга",
  contact: "+7 900 000-00-00",
  objectType: "Квартира",
  area: "96",
  location: "Москва",
  district: "Хамовники",
  service: "Полный дизайн-проект",
  startTiming: "В течение 3 месяцев",
  budget: "Более 180 тыс.",
  decisionMaker: "Ольга",
  source: "Рекомендация",
  consent: true
}
```

- текстовые и селектные поля по умолчанию равны `""`;
- чекбокс по умолчанию равен `false`;
- `consent` — единственное булево поле;
- необязательные поля могут оставаться пустыми;
- ключи не переименовываются без обновления `config.js`, документации и тестов.

## 2. Поля

### Обязательные — 9

| Ключ | Подпись | Тип | Правило |
|---|---|---|---|
| `name` | Имя | текст | 2–50 символов; буквы, пробел, дефис, апостроф |
| `contact` | Контакт | текст | телефон из 11 цифр с 7/8 **или** `@` + 4–32 символа |
| `objectType` | Тип объекта | селект | `Квартира`, `Дом`, `Другое` |
| `area` | Площадь, м² | текст | число от 1 до 10 000, не более 1 знака после запятой |
| `location` | Локация | селект | один из пяти вариантов |
| `service` | Услуга | селект | один из пяти вариантов |
| `startTiming` | Когда начнётся ремонт | селект | один из шести вариантов |
| `budget` | Бюджет на реализацию, ₽/м² | селект | один из пяти вариантов |
| `consent` | Согласие | чекбокс | должен быть отмечен |

### Необязательные — 3

| Ключ | Подпись | Тип | Правило | Влияет на статус |
|---|---|---|---|---|
| `district` | Район или населённый пункт | текст | ≤ 100 символов | нет |
| `decisionMaker` | Кто принимает решение о заказе | текст | ≤ 100 символов | нет |
| `source` | Откуда узнали о студии | селект | один из шести вариантов | нет |

## 4. Шаги формы

| Шаг | Заголовок | Поля |
|---:|---|---|
| 1 | Контакты | `name`, `contact` |
| 2 | Объект | `objectType`, `area` |
| 3 | Локация | `location`, `district` |
| 4 | Проект | `service`, `startTiming` |
| 5 | Бюджет | `budget` |
| 6 | Дополнительно | `decisionMaker`, `source`, `consent` |

Каждое поле входит ровно в один шаг. `fieldStepIndex()` использует этот массив,
чтобы открыть нужный шаг с экрана проверки.

## 5. Результат квалификации

```js
{
  status: "Нужно уточнить",
  reasons: [
    "География объекта требует уточнения, включая формат работы",
    "Бюджет не подтверждён или ниже типового"
  ]
}
```

- `status` — одна из трёх строк: `Приоритетная`, `Нужно уточнить`,
  `Не наш формат`;
- `reasons` — массив непустых причин на русском языке;
- при `Приоритетная` массив содержит одну причину BR-01;
- при остальных статусах причины идут в порядке правил BR-02…BR-09, затем BR-10;
- результат не содержит персональных данных и не сохраняется отдельно.

Подробнее — в [`QUALIFICATION-RULES.md`](QUALIFICATION-RULES.md).

## 6. `localStorage`

Приложение использует два ключа.

### `forma.draft`

```json
{
  "answers": {
    "name": "Иван",
    "contact": "@ivan_test",
    "objectType": "Дом",
    "area": "140"
  },
  "step": 2,
  "savedAt": 1770000000000
}
```

- `answers` — текущий объект ответов;
- `step` — номер шага от 1 до 6;
- `savedAt` — время последнего сохранения;
- запись происходит при каждом `input` и `change`;
- при отправке ключ удаляется.

### `forma.result`

```json
{
  "answers": {
    "name": "Ольга",
    "contact": "+7 900 000-00-00",
    "objectType": "Квартира",
    "area": "85",
    "location": "Москва",
    "service": "Полный дизайн-проект",
    "startTiming": "В течение 3 месяцев",
    "budget": "Более 180 тыс.",
    "consent": true
  },
  "submittedAt": 1770000000000
}
```

- результат нужен, чтобы открыть карточку после перезагрузки;
- при «Новая анкета» ключ удаляется;
- при повреждённом JSON ключ удаляется, приложение показывает начальный экран.

### Правила защиты

- все операции обёрнуты в `try/catch`;
- `loadDraft()` проверяет форму объекта и диапазон шага;
- `loadResult()` проверяет форму объекта;
- `mergeAnswers()` отбрасывает значения неверного типа;
- данные никогда не покидают браузер.

## 7. Инварианты

- 12 полей: 9 обязательных, 3 необязательных;
- 6 шагов, каждое поле ровно в одном шаге;
- 3 статуса и 14 бизнес-правил;
- `area` — строка в форме, число при квалификации;
- необязательные поля не меняют статус;
- статус не показывается на клиентских экранах;
- отправка не блокируется статусом;
- при отправке черновик удаляется, результат сохраняется;
- при «Новая анкета» удаляются оба ключа;
- приложение не делает сетевых запросов и не использует реальные данные.
